# DSH 论文阅读器

在 DSH 对话的右侧阅读 PDF。点击“解释”或“翻译”会将带文件名和 PDF 页码的选段直接发送到当前会话，无需再按回车；“提问”仍先插入草稿，便于补充问题。已有的输入框草稿和附件保持原样。讨论结束后可一键生成阅读笔记：插件把总结指令插入会话草稿，AI 回顾整段讨论生成 Markdown 笔记，并用自己的文件工具保存到工作区根目录的论文标题文件夹下。

## 安装

**给其他用户**：在 DSH 插件管理器中选择从 GitHub 安装，仓库地址 `Pierre1231/dsh-paper-reader`，然后启用 `dsh-paper-reader` bundle。仓库已包含构建好的 `lib/`，无需自行构建。如果 DSH 提示需要重启，保存好会话并依提示操作。本插件使用 DSH 客户端 PDF 文档预览、右侧栏和会话输入插槽；实际可用性取决于安装版的接口和插件管理状态。

**本地开发**：克隆后执行 `npm install` 和 `npm run build`，在 DSH 插件管理器中添加本目录作为本地插件并启用。

首次打开工作区 PDF 时，可在右侧文档预览器选择“论文阅读”。对话顶部的“打开本地论文”入口可选择其他目录下的 PDF（例如 Zotero storage）。本地选择的文件仅在当前浏览器页面内读取，刷新后需要重新选择；这不会让助手获得对文件路径或全文的读取权限。工作区 PDF 在当前页面会话期间记住页码和缩放。

选择 PDF 文字后使用“解释 / 翻译 / 提问 / 复制”。没有选区时，将鼠标在正文段落上停留约 120ms，也会整框连续高亮该段并显示同样的操作；移动到菜单上不会立即关闭，滚动或移出后会自动清理。双栏论文按水平重叠和行间距尽量分栏识别，复杂排版仍可能需要手动划词。解释和翻译通过宿主的会话发送接口直接提交，模型忙碌时采用宿主的排队模式；不会把输入框中的其他草稿或附件一起发送。发送接口不可用或发送失败时，原文或图片暂留在阅读器中，可显式“重试发送”、复制或放弃。

解释和翻译始终发送完整原文及来源，不先写入输入框。“提问”时，超过 240 个字符或三行的选段会作为内联引用 chip 加入，输入框只保留 `@PDF选段 · 第N页` 和一行简短指令，不再生成原生文件附件卡片。chip 的 `ref` 保存版本化 JSON（文件名、页码和完整选段），随语义草稿持久化；发送时由注册的 `paper-reader-quote` source 将 chip 展开为完整原文与页码。短选段仍直接插入原文，chip 插入不可用时回退到全文插入。

悬停带英文编号图注的 Figure / Table 区域时，与正文同样在约 120ms 后显示高亮和“解释 / 复制”。高亮不等待高清截图，截图在界面显示后后台准备；提前点击会显示“正在准备清晰图表”，完成后继续所选操作，无需再次点击。解释会等高清 PNG 准备完成后，将图片和“解释这张图表”一并直接发送到当前会话，页码保留在图片文件名中；复制将图片写入剪贴板。发送失败时保留图片供重试；图片剪贴板不可用时，提示复制带来源和图注的文字。发送给支持图片输入的模型后，模型才能看到图表。

## 阅读笔记

- 阅读器工具栏的「笔记」按钮与会话头部的笔记图标常驻可用。点击把总结指令插入当前会话草稿（不自动发送），检查后即可发送。
- AI 回顾整段讨论（你的提问与它的解答都在对话上下文中），开头写 3–5 句论文概述，之后按论文章节整理每条“疑问 + 解答 + 重要性”，保留被纠正后的正确理解与“是不是这样理解”的确认点，忽略翻译/复制等工具操作和闲聊。
- AI 用自己的文件工具把笔记保存到 `工作区根目录/{论文标题}/论文笔记.md`，文件夹名由文件名按统一规范生成（去 `.pdf` 后缀、非法字符转 `-`、最长 60 字符、词边界截断）；保存后只在对话里回复路径和要点统计。
- 会话头部的笔记按钮不带文件名，插入的是通用指令，由 AI 根据对话内容判断论文并套用同一命名规范。

## 视觉与交互

- 工具栏、菜单和提示采用宿主语义颜色与系统 UI 字体；独立使用时提供亮/暗色回退。PDF、图表和原批注保持原色。
- 阅读容器宽度 ≤520px 时工具栏分为两行，320px 侧栏也保留文件名和主要操作。
- 图表采用透明内部与蓝色外框，段落采用边框内连续填充。浮层按阅读区边界避让，顶部空间不足会放到下方。
- 在 PDF 内按住左键拖选时，选区两端由插件按位置计算：鼠标经过分式、上下标和公式编号前的空白不会让选区跳到页尾，可完整选中公式；拖到阅读区上下边缘自动滚动。双击/三击、Shift 扩选、键盘与触屏选择保持浏览器原生行为。悬停段落时，公式的上下标、分子分母与主行合并为同一段。
- 同目标内鼠标微动（<5px）不重置 120ms 计时；菜单获得焦点或鼠标经过安全路径时保持打开。Escape 关闭并回焦，菜单内方向键移动焦点。
- 成功反馈在工具栏短暂显示约2秒，失败与待重试引用保留可操作提示。减少动效和系统高对比模式均有独立样式。
- 图表几何按渲染代次缓存。未认领的截图预取最多1个，操作已认领的任务继续完成；完成图片缓存上限4张或16MiB，关闭文档即释放。
- PDF 解析固定在插件自建的 Worker 线程中运行，并等待其“就绪”握手。宿主页面里即使已有在主线程运行的 pdf.js（`globalThis.pdfjsWorker`），也不会被拖回主线程；Worker 确实无法创建时，工具栏会提示“PDF 正在主线程解析，可能卡顿”，不再只在控制台留一条警告。
- 同一份 PDF 按内容（而不是 Uint8Array 对象）识别：宿主重新渲染时传入新的数组、或侧栏卸载后重新挂载，都会复用已解析的文档，不再整篇重新解析；无人使用的文档保留 60 秒后释放。
- 页面绘制采用共享分帧队列，优先处理可见页，每帧一个绘制片段，预加载上下各 800px。画布按内存预算保留：清晰位图最多 8 页 / 128 MiB，超出时最远的页缩成 1/4 尺寸的占位图（最多 24 MiB），回滚时立即显示占位图并在后台重绘清晰版本，不再出现空白页和“正在加载”。跨页选区覆盖的页不会被缩小。
- 文字层只为视口附近 240px 内的页面构建，每页只构建一次（缩放只改变 CSS 变量），按 6ms 时间片分批、在脱离文档的分组里生成后一次插入；最多保留 12 页文字层。文字层带 `translate="no"`，避免翻译类扩展改写选区。测量与渲染使用同一显式语言（PDF 的 /Lang，否则 en）：中文宿主中 pdf.js 自带文字层会因空 `lang` 用错字体，长行宽度偏差约 30px，此处与 PDF 本身误差在 1–2px。
- 滚动期间暂停悬停扫描和未认领截图，停稳 180ms 后重新命中指针位置；已点击的截图操作继续完成。页码更新按帧合并，页内读取当前页，跳页使用二分查找。
- 首次绘制直接使用页面画布；缩放在离屏画布中重绘，清晰的新版本准备完成前保留上一帧；文字层在缩放时保留并随 CSS 缩放，不再重建。
- 图表悬停所需的内嵌图像位置只在页面有图注时、空闲时读取一次；不再为每次绘制额外向 Worker 请求一遍完整操作列表。

## 性能诊断（真实 DSH 验收）

隔离浏览器测试不能代替真实 DSH 中的体验。v0.6.0 起插件始终记录低开销的诊断数据，在 DSH 中可直接导出：

- 在阅读器内按 **Ctrl+Alt+D**（macOS 为 ⌘+⌥+D）：约 2 秒的环境探测后，诊断报告 JSON 复制到剪贴板（失败时输出到控制台）。
- 或在 DSH 开发者工具控制台运行 `await __dshPaperReaderProbe()`，再执行 `copy(JSON.stringify(__dshPaperReaderTrace(), null, 2))`。

报告中重点看：

| 字段 | 含义 |
|---|---|
| `worker.mode` | `thread` 为后台线程；`main-thread` 表示解析在 DSH 主线程，`reason` 给出原因 |
| `environment.hostHadMainThreadPdfWorkerAtLoad` | 宿主页面是否已在主线程加载过 pdf.js Worker |
| `environment.patchedApis` | 被宿主或扩展改写过的 DOM / 计时 API（非原生实现） |
| `opens` / `mounts` / `events` 中的 `same-content-new-array` | 文档是否被反复打开、阅读器是否被反复挂载，以及宿主是否用新数组传入同一文件 |
| `pages[].canvasFirstSliceMs` / `canvasMainMs` / `canvasWallMs` | 等待 Worker 的时间 / 主线程实际绘制时间 / 总耗时 |
| `pages[].textContentMs` / `textBuildMainMs` / `textMaxSliceMs` | 文字提取 / 文字层主线程耗时 / 最长单片 |
| `summary.longTasks`、`longAnimationFrames` | 长任务；`supported: false` 表示宿主不支持该指标，不代表没有长任务。长动画帧会列出造成阻塞的脚本来源 |
| `probe.framesPerSecond` / `taskHopMs` | 帧率是否被宿主节流 / 事件循环延迟 |
| `probe.liveInsert300Ms` / `detachedInsert300Ms` / `createOnly300Ms` | 宿主对逐个插入 DOM（pdf.js 原方式）与一次性插入的实际代价，以及单纯创建元素的代价 |

优化前版本已独立存档：[运行版和源码 ZIP](../archives/dsh-paper-reader/20261104T165145939634Z/plugin.zip)、[恢复说明](../archives/dsh-paper-reader/20261104T165145939634Z/RESTORE.md)。存档经实际解压与29个文件的SHA-256校验，不随此版本更新。

## 限制

- 扫描版 PDF 没有可选文字，当前未集成 OCR。
- PDF 文件读取受 DSH 宿主和浏览器的限制。浏览器选取的外部文件不支持刷新后恢复。
- 非标准字体、极长文件或特殊 PDF 可能需要更多兼容性测试。
- 图表识别目前依赖位于图表下方的英文编号图注，再按画布中的全部可见像素收紧外侧空白；不会按主色或最大连通块丢弃浅色面板。鼠标停在收紧后的图表外部空白时不会触发图表菜单。跨页、图注在上方或侧方、无编号图注及复杂排版仍可能需要手动截图。
- 附件按 PDF 原始页面重新渲染，显示缩放与输出分辨率分别计算；裁剪区域保留少量边缘，避免切掉线条。画布读取或高清渲染失败时保留保守的几何区域或屏幕截图作为回退。
- 本插件没有实现全文翻译、持久化批注或 Zotero 数据库同步。自动发送仅用于用户点击的解释和翻译操作，提问与笔记仍保留草稿确认。

## 开发验证

运行 `npm run typecheck`、`npm test` 和 `npm run build`。`npm run test:parity`（设置 `PAPER_TEST_PDFS` 为逗号分隔的 PDF 路径）逐个 span 比对文字层与 PDF 本身的宽度和基线；`npm run test:scenarios`（设置 `PAPER_TEST_PDF`，可传入多个 client.js 对比）在 6 倍 CPU 降速下复现三种宿主行为：宿主已在主线程加载 pdf.js Worker、宿主用新数组反复传入同一文件、读到末尾后跳回第 1 页；`npm run test:stress` 对比 Worker 正常/被阻止与轻/重宿主页面下的帧间隔和长任务。所有浏览器脚本在非 Windows 环境需设置 `CHROME_PATH`。`tests/browser-server.mjs` 提供隔离的模拟宿主测试页面：设置环境变量 `PAPER_TEST_PDF` 为本地 PDF 路径后，在项目目录运行 `node tests/browser-server.mjs`。测试页面不连接 DSH，也不能替代在真实 DSH GUI 中的验收。设置 `PAPER_TEST_URL` 后可运行 `npm run test:scroll` 检查跨页选区保护、页面释放和滚动暂停悬停；`npm run test:perf` 采集 2× 像素比下的下滚/返回帧间隔、页面几何读取、画布保留和 CPU profile，结果写入 `test-results/performance/`。通过 `PERF_LABEL` 区分报告名，`PERF_ASSERT_BOUNDED=1` 检查折叠光标不阻止页面回收。

PDF.js 及其 CMap、字体数据的许可证随插件分别包含在 `PDFJS-LICENSE`、`PDFJS-CMAP-LICENSE`、`PDFJS-FONT-FOXIT-LICENSE` 和 `PDFJS-FONT-LIBERATION-LICENSE` 中。
